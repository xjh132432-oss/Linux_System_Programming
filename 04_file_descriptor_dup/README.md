- 理解打开文件描述（Open File Description）。
- 掌握 `dup()`。
- 掌握 `dup2()`。
- 理解共享文件偏移量。
- 区分 `dup()` 和多次 `open()`。
- 理解关闭一个复制出来的文件描述符不会影响其他引用。

## 2. 核心概念

### 2.1 文件描述符与打开文件描述

文件描述符（FD）是进程文件描述符表中的一个整数索引。

打开文件描述（Open File Description）是内核维护的对象，记录文件偏移量、文件状态标志等信息。

文件描述符与打开文件描述之间的关系：

- 一个文件描述符指向一个打开文件描述。
- 多个文件描述符可以指向同一个打开文件描述。
- 多次调用 `open()` 打开同一个文件，通常会创建独立的打开文件描述。

### 2.2 dup() 的共享关系

使用 `dup()` 复制文件描述符：

    int fd2 = dup(fd1);

此时：

- fd1 和 fd2 是不同的整数编号。
- fd1 和 fd2 指向同一个打开文件描述。
- 两者共享文件偏移量。
- 关闭其中一个描述符，不会自动关闭另一个。

### 2.3 dup() 与 open() 的区别

使用 `dup()`：

    int fd2 = dup(fd1);

fd1 和 fd2 共享文件偏移量。

分别调用两次 `open()`：

    int fd1 = open("offset.txt", O_RDONLY);
    int fd2 = open("offset.txt", O_RDONLY);

两个描述符对应独立的打开文件描述，文件偏移量互不影响。

## 3. dup() API

头文件：

    #include <unistd.h>

函数声明：

    int dup(int oldfd);

参数：

- oldfd：需要复制的文件描述符。

返回值：

- 成功：返回新文件描述符，编号为当前最小可用 FD。
- 失败：返回 -1。

示例：

    int fd2 = dup(fd1);

## 4. dup2() API

头文件：

    #include <unistd.h>

函数声明：

    int dup2(int oldfd, int newfd);

参数：

- oldfd：原文件描述符。
- newfd：指定的新文件描述符编号。

返回值：

- 成功：返回 newfd。
- 失败：返回 -1。

特点：

1. 可以指定目标文件描述符。
2. 如果 newfd 已经打开，成功复制前会先关闭它。
3. 如果 oldfd 与 newfd 相同且 oldfd 有效，则直接返回 newfd。

示例：

    int fd2 = dup2(fd1, 10);

成功后，fd2 的值为 10。

## 5. 共享文件偏移量验证

测试文件：

    ABCDEFGHIJ

执行过程：

| 操作 | 读取结果 | 共享偏移量变化 |
|---|---|---|
| 初始状态 | — | 0 |
| read(fd1, buffer, 2) | AB | 0 → 2 |
| read(fd2, buffer, 2) | CD | 2 → 4 |
| read(fd3, buffer, 2) | AB | 独立偏移量 0 → 2 |
| close(fd1) | — | fd2 仍然有效 |
| read(fd2, buffer, 2) | EF | 4 → 6 |

其中：

- fd1：第一次 open()。
- fd2：dup(fd1)。
- fd3：第二次 open()。

最终验证：

- fd1 和 fd2 共享文件偏移量。
- fd3 拥有独立的文件偏移量。
- 关闭 fd1 后，fd2 仍然可以正常读取。

## 7. 本日总结

本日最重要的结论：

文件描述符是进程访问打开文件描述的入口，不等于打开文件描述本身。

dup() 复制的是文件描述符，而不是重新打开文件，因此复制得到的描述符共享同一个打开文件描述及其文件偏移量。

多次 open() 则会创建独立的打开文件描述，因此文件偏移量相互独立。
